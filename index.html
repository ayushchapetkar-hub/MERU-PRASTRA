01 — Origins

About Meru-Prastāra

What is Meru-Prastāra?

Meru-Prastāra ("the expansion of the mountain") is a triangular tabulation method used in classical Indian prosody (Chandaḥśāstra) to enumerate every possible arrangement of light (laghu) and heavy (guru) syllables in a metrical line of a given length. Each row of the figure lists, in order, the number of syllable-patterns containing 0, 1, 2, … heavy syllables — the same integers that later appear in Europe as the entries of Pascal's Triangle.

Pingala (c. 3rd–2nd century BCE)

The sage Ācārya Piṅgala, in his Chandaḥśāstra, first described the rule for building this triangular table to count metrical patterns, along with the Prastāra (enumeration), Naṣṭa and Uddiṣṭa (encoding/decoding) algorithms — procedures that read like specifications for array-based algorithms nearly two thousand years before computers existed.

Halāyudha (10th century CE)

Writing a commentary on Piṅgala's text, Halāyudha named the triangular figure Meru-Prastāra and stated its generating rule explicitly: every interior number is the sum of the two numbers above it. This is, verbatim, the recurrence relation used in the modern Dynamic Programming solution for binomial coefficients.

Why it is important

  • It shows a complete, rule-based, tabular algorithm recorded in India over a millennium before Blaise Pascal (1653).
  • It demonstrates that "building today's row from yesterday's row" — the core idea of Dynamic Programming — is an old, well-understood technique in Indian mathematics.
  • It connects linguistics (metre), combinatorics (counting) and computation (algorithmic rule) in a single figure.

    05 — Under the Hood

    Algorithm

    Pseudocode

    function buildMeruPrastara(rows):
    triangle = empty list

    for i from 0 to rows - 1:
        row = new array of size (i + 1)
        row[0] = 1
        row[i] = 1                  // edges are always 1

        for j from 1 to i - 1:
            row[j] = triangle[i-1][j-1]   // left parent
                    + triangle[i-1][j]    // right parent
                                            // <- Halayudha's rule
        triangle.append(row)

    return triangle

    Complexity & Limitations

    • Time Complexity: O(n²) — every one of the ~n²/2 cells is computed exactly once from its two parents.
    • Space Complexity: O(n²) to store the full triangle; O(n) if only the current and previous rows are memoised.
    • Limitation 1: Values grow combinatorially; beyond ~1024 rows, native 64-bit integers overflow (this app uses JavaScript BigInt to stay exact).
    • Limitation 2: Rendering very large triangles (100+ rows) becomes a UI / readability problem before it becomes a computational one.
    • Limitation 3: The naive recurrence recomputes nothing, but a single nCr lookup still costs O(n) if the whole triangle isn't cached, since each row needs the one before it.

    09 — Project Report

    Documentation

    Problem Statement

    Ancient Indian prosody already solved a combinatorial enumeration problem — counting syllable patterns — using a triangular, rule-based table. This project asks: can that 2000-year-old method (Meru-Prastāra) be expressed, exactly, as a modern Computer Science artefact (an array built by Dynamic Programming), and does doing so reveal genuine CS applications?

    Conceptual Mapping

    Meru-Prastāra's triangular tablet arrangement is structurally identical to Pascal's Triangle; its row-from-row construction rule (Halāyudha) is structurally identical to a Dynamic Programming recurrence; its rows are literally rows of binomial coefficients, i.e. combinatorics.

    Algorithm

    Row 0 is seeded as [1]. Every subsequent row's edge values are 1; every interior value is the sum of the two values above it in the previous row. See the Algorithm section for pseudocode and a flowchart.

    Applications

    Dynamic Programming, AI/ML feature/kernel computations, probability and statistics, competitive programming, computer graphics (Bézier curves), binomial expansion, and combinatorial cryptography constructs. See the Applications section for details on each.

    Complexity

    Time: O(n²). Space: O(n²) full storage, or O(n) with row-memoisation only.

    Limitations

    Integer overflow beyond native precision (mitigated here with BigInt), rendering cost for very large triangles, and the fact a single nCr lookup still needs the row built up to it.

    Conclusion

    Meru-Prastāra shows that the logical structure behind Pascal's Triangle and Dynamic Programming was documented in India by Piṅgala and named and formalised by Halāyudha, centuries before Pascal (1653). It is one clear, verifiable example of an Indian Knowledge System that maps directly onto a core Computer Science technique still used today.

    10 — Closing

    Conclusion

    Piṅgala's Chandaḥśāstra first laid out the rule for enumerating syllable patterns in a triangular table. Centuries later, Halāyudha named this figure Meru-Prastāra and stated its build rule in the exact form Computer Science now calls a Dynamic Programming recurrence: each cell equals the sum of the two cells above it. When Blaise Pascal published his Traité du triangle arithmétique in 1654, he was describing, independently, the same structure that Indian prosodists had already been using for over a thousand years.

    This project shows that Meru-Prastāra is not a historical curiosity sitting beside Computer Science — it is a Computer Science structure, expressed in the vocabulary of classical Indian metrics. It stands as direct evidence that Indian Knowledge Systems contributed working computational ideas — arrays, recurrences, and combinatorics — to the discipline we practise today.
